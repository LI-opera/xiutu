# 资料章节检索评测（section-retrieval-eval-v2）

回答一个问题：**不靠人工关系表，只凭文字内容，能不能找对资料章节？** 这是"资料进来后自动处理、不再手写关系表"的前提。只做离线评测，不调用大模型、不接入 AI 分析。

## 怎么测

- **资料块**：5 份区域资料按 `###` 小节切块。`##` 下第一个 `###` 之前的导语单独成一块；每块带标题路径（如"6. 接头座合… > 6.3 A 类连接"）。实现见 `backend/app/retrieval/section_search.py`。
- **查询**：每道题的每个选项各一条，内容是"题目（去掉题号）：选项"，如"快插接头是否推至止挡并可靠锁止：未完全座合"。两个模板里重复的查询只算一次。
- **检索范围**：只在该题所属区域的资料里找，和分析时一致。
- **标准答案**：人工关系表 `backend/app/topics/analysis_context_v1.json` 里该题（及该选项）引用的章节，去掉每次都会带上的"必带章节"。
- **排名单位（v2）**：先按小节检索，再把结果合并成整个 `##` 章节，同一章节只占一个名额。现有关系表大多按整章引用（140 处 `##`，47 处 `###`），分析时发给 AI 的也多是整章。
- **算命中**：标准答案是 `##` 章节时，这个章节进前 k 就算命中；是 `###` 小节时，包含它的章节进前 k 就算命中（整章里一定有这个小节，但发送的内容会比只发这个小节多）。
- **v1 → v2**：v1 按小节排名，同一章节的几个小节会挤占名额。v1 结果未达到及格线（三路融合前 5 名召回率 0.862），分析后改为按章节排名，报告里保留按小节的分数作对照。及格线的数值没有改。
- **指标**：前 k 名召回率（标准章节里被找到的比例，k = 3/5/10），MRR（第一个正确结果排位的倒数，取平均）。

## 三路检索

| 检索方式 | 看什么 |
| --- | --- |
| 精准查找（exact） | 故障码、零件/插头代号、工具编号必须一字不差，如 G31 和 G71 是两样东西 |
| 关键词（bm25） | 词的重合程度：少见的词更值钱，长段落不白占便宜 |
| 向量（dense） | 意思相近即可，如"插接不到位"和"未完全座合"；用本地 multilingual-e5-small |
| 融合 | RRF：每一路给排在第 n 位的结果加 1/(60+n)，几路都靠前的排最前 |

## 公平规则

1. **查询里不放题号**。资料里本来就有"题号 → 第几节"的对照表，带着题号查，等于直接看答案。
2. **导航章节不参与检索**，比如"阅读入口""与现有 AIR 问题的对应关系""提供给 AI 时怎样使用""来源"（规则见 `config.json` 的 `navigation_sections`）。新资料里不会有这样的对照表，它们不能当检索的依据。
3. 报告另外给一个"查询带题号、导航章节也参与"的对照分数，只作对照，不作为结论。
4. **及格线在看到结果之前写定**（`config.json` 的 `pass`）：融合后前 5 名召回率 ≥ 0.90，且每份资料 ≥ 0.80。不因结果修改及格线；如果要改评测方法，升级 `version` 并说明原因。

离线测试 `tests/unit/test_section_retrieval.py` 会检查：查询里没有题号、标准答案不含必带章节、所有标准章节在排除导航章节后仍然找得到。这条测试抓到过一次单字母题号（X-01）没被去掉的问题。

## 怎么运行

```powershell
# 完整：三路都跑，需要本地 E5 模型（.local-data/models/multilingual-e5-small）
uv run python -B scripts/section_retrieval_eval.py

# 只跑精准查找和关键词
uv run python -B scripts/section_retrieval_eval.py --no-dense
```

报告在 `.local-data/evals/section-retrieval/<时间>/report.md`，内容包括总表、按资料的分数、对照分数，以及没找全的查询（标准答案和实际排名前 5 的对照）。资料块的向量会缓存到 `.local-data/evals/section-retrieval/cache/`。

## 局限

- 标准答案是人工关系表，它本身也可能漏标或多标。没找全的查询要人工看一下，判断是检索错了还是标准答案可以讨论；
- 只有一个车型的 5 份资料、约 280 条查询；
- 只测"找没找到"，不测找到的内容发给 AI 后建议会不会变好。那要接入后用 AI 建议评测集（`evals/area-advice/`）来验证。

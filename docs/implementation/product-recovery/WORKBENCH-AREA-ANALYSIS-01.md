## 通用运行流程

1. 页面提交病例 ID、区域 ID、预期记录版本。
2. 后台核对病例归属，从病例绑定的模板读取区域问题。
3. 按问题所属区域筛选有效已保存答案；其他区域不混入，未记录项保持未知。
4. 按模板版本和区域 ID 查询资料关系，取得数据库中的全文。
5. 冻结车辆、主诉、故障码、本区答案、问题定义、资料正文和版本，交给同一套 `area-advice-v1` 提示词与结构。
6. 单次调用生成，解析并独立保存本区结果；页面显示来源、记录版本、用量、步骤和依据。

没有针对压力、气路等区域的生成分支。区域差别来自数据与文档，不来自专门提示词。保留权限、结构解析、输入预算和防重复请求，不叠加旧关键词、操作清单或技术内容发布门禁。无效引用不伪造可点击依据。

请求身份按本区实际输入哈希计算。修改另一区域导致病例总 revision 增加，不会单独使本区结果过期；本区答案、车辆主诉、模板、文档或提示词变化才改变输入身份。历史输入与结果不被覆盖。相同输入已有尝试时复用记录，不自动重试失败或未知请求。

## 后续如何登记资料

`backend/app/topics/area_reference_manifest_v1.json` 是本轮资料导入清单，**不是运行时关系表**。`scripts/seed_area_references.py` 将清单解析为版本化正文与数据库关系。

新增区域资料时登记唯一文档 ID、版本、区域 ID、源文件或章节，绑定到适用模板版本，然后运行导入。新区域不需要改生成函数。已有文档同版本正文变化会被拒绝，需创建新版本；已有关系切换版本应明确更新登记，不默默覆盖历史版本。当前没有新增资料管理后台页面。

本机迁移及首次导入入口：`python -B -m scripts.install_area_references`（使用项目 `.venv`）。仅接受预期本机隔离数据库与既有迁移版本。已执行增量迁移 `0020_area_analysis`、`0021_area_input_identity`，未删除原病例、观察或历史分析。

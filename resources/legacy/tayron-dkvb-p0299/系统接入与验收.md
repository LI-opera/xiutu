# 系统接入与体验验收说明

这是开发交接资料，不是本轮执行授权。当前仅制作资料，未实施WP-11、WP-12或更改5180预览。

## 1. 输入边界

整包为`DKVB-P0299-DEMO-v1`，只进入独立synthetic专题范围，`formal_usable=false`。真实原页作为演示中的来源参照，并不把混合了虚构规格的整个专题升级为正式维修知识。

优先供检索的文件：维修知识手册.md、规格与判断关系.md。来源与图纸.md提供源文件导航；图片需要由界面展示，不假设当前向量检索会理解图片。

禁止将演示病例与操作脚本.md、cases/expected.json、系统接入与验收.md及制作检查结果.md作为维修知识索引。cases/observations.json也不索引；由模拟器在用户执行当前检查后，只提供对应的观察片段。未来观察不提前暴露。

采用明确文件白名单：仅维修知识手册.md、规格与判断关系.md作为本包正文检索输入；来源与图纸.md仅用于来源导航。README含体验剧情，资料整理记录含改动说明，二者也不得进入检索或诊断模型上下文。knowledge.json与manifest.json是导入控制资料，不作为维修正文；不得递归扫描整个目录、沿链接自动抓取测试者剧本或直接把整个资料包拼入模型上下文。

模型可看到通用条件分支和当前已提交的观察，不可看到病例编号对应的隐藏故障、未来读数、预定阶段路径或结局。文件排除声明只是接入要求；本轮没有运行导入器，实际隔离须在后续接入时验证。

`knowledge.json`是本文定义的作者级数据，不是xiutu-v5现有schema。ID不冒充数据库UUID，状态不冒充服务端审核。需经适配创建真实文档版本、证据、规格和观察映射，不能绕过权限／来源／预算检查。

## 2. 最小适配清单

| 本包对象 | 当前系统适配点 | 成功标志 |
|---|---|---|
| CHK-01—11 | 诊断步骤、状态持久化、观察输入 | 能保存当前步骤，刷新恢复，按结果选择下一步 |
| DS-01 | 同条件十进制差值比较 | 展示原始值与±30演示范围，保留synthetic标志 |
| DS-02 | 多帧比较及组合判断 | 不用平均值掩盖异常，不把运行目标当常数 |
| FS-02 | 方法约束／引用解释 | 不生成空气系统保压测试结论 |
| CHK-07/11 | 明确的维修后验证 | 不强塞当前仅允许的冲突复测模板，不重复扣除已完成调用预算 |
| REL-01—07 | 新的可信关系映射或经验证的语义支持 | 可追溯前提与范围，不冒用WP-10原有两种模板 |
| 页图和来源 | 文档版本＋PDF页＋图号 | 点引用可打开正确版本原图，不只显示裸路径 |
| 阶段与修改 | 当前观察、失效比较和历史记录 | 修改旧观察时，依赖结果同步失效，旧历史不删除 |

已有WP-10有界工况和动作表达不能完整覆盖DEMO_STATIC、DEMO_LOAD_STABLE、多帧比较和本专题判断关系。若未经适配直接上传后出现拒绝，应报告具体不支持点，不把正文改写成“发动机关闭，engine=off”来假装动态步骤已兼容。

## 3. 建议用户界面

上方固定显示“探岳DKVB／P0299 · 模拟维修演示”。主区域只展示当前检查卡，包含目的、来源图、简短动作和结果输入；右侧显示已知证据与尚未解决项。UUID、内部receipt和原始JSON放在展开的调试区。

初始用户只选病例和提交客户描述；界面不能展示隐藏故障答案。每次步骤提供以下动作：查看原文、提交观察、暂未检查、无法判断。涉及处理的卡显示“记录模拟处理完成”，不冒充实车诊断设备控制。

中间处理后显示前后比较，明确区分“改善”“当前检查恢复”“演示病例完成”。生成报告必须由用户触发。

## 4. 分阶段接入，避免又花多轮只做后台

1. 先读取资料并打通一条主病例：用户输入症状→模型或明确标记的模拟执行器提出检查→用户提交观察→下一步变化。保留必要引用和真实状态。
2. 加入A与B分叉，证明管路处理后改善不足会继续，完全恢复则结束，不强制第二故障。
3. 加入C至F，验证负例、补问和未定位交接。最后验证刷新恢复、旧结果失效和报告。

这不是要求一次实施所有工作包；由协调窗口把步骤拆入明确授权的工作包。不要为演示绕过现有鉴权、资料范围或硬规格门禁；缺功能在隔离synthetic场景做明确适配。

## 5. 体验验收标准

- 主病例A能够经历“漏点处理后改善但未恢复→继续调节方向→最终模拟复检通过”。
- 病例B不强制多修一项；病例C不伪造漏点；D不强行诊断部件；E能补问后前进；F能有内容地交接。
- 同一病例改变一项关键观察，下一步或结论实际改变。
- FS-02被正确引用，空气系统不会沿用冷却系统保压标准。
- 模型若使用，不能看到隐藏答案或未来观察；输出与证据、比较结果分别可查。
- 引用带版本和页码，模拟阈值不显示为原厂标准。
- 最终报告仅包含实际已输入的事实与模拟动作，不自动生成未检查部件正常结论。
- 刷新后还在正确阶段；切换病例不会保留上个病例的通过状态。

上面的项目是未来系统接入验证，不是本包已经运行通过的项目。本轮制作检查仅核对文件、链接、源副本哈希和模拟数据逻辑。
